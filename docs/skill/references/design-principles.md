# Design Principles

- The 3D model is the compiler, not the runtime. One structured export feeds multiple front ends (full 3D, Sierra rooms, top-down, text parser).
- Fixed scene sequence (Gold Rush / King's Quest 4 model). Inside each scene the player can try any verb against any canon object and get a real response, including failure that costs something.
- Verb freedom is the replay lever inside a linear spine. Consequences compound via the dated canon.
- Forks are one-shot: diverge at a decision point, play the branch, forced reconvergence at a load-bearing event. Tree never grows past depth one.
- Load-bearing events happen because the game needs them (e.g., Billy Sunday revival as reconvergence even in a Smith-goes-to-Missouri fork).
- Post-scene dossier: period newspaper or historian's note summarizing what shifted. Doubles as canon documentation.
- Legacy/bloodline system: a saved life in one scene reappears as descendants across later scenes.
- Crisis states (active / resolved / aftermath) as a schema field alongside from-year / to-year.
- Threads: a line of interaction that runs to a clear end, then waits. Multiple open, pull one at a time. Abandoned threads leave scars rather than hard blocks.
- Priority stack: several threads visible, but each runs to exhaustion before the next opens. Exhaustion should hand you something that points at the next priority.
